JSON 정리에 성공했는데 긴 숫자 ID가 바뀌거나 같은 키의 값이 사라졌다면 **결과를 원본에 덮어쓰지 말고 원본 사본과 비교하세요.** 매니툴 JSON 정리·검증기는 데이터를 자바스크립트 값으로 읽은 뒤 다시 JSON으로 저장합니다. **올바른 JSON입니다.**라는 안내는 문법 검사 결과이며 원문이나 모든 값의 보존을 보장하지 않습니다. 매니툴 운영팀이 현재 구현과 아래 예시를 확인했습니다.

## 시작 전에 준비할 것

정리 전 원문을 별도 텍스트 파일에 보관하세요. 정리에 성공하면 입력창이 결과로 교체되므로, 정리된 입력창만 남아 있다면 없어진 정보를 그 결과에서 복구할 수 없습니다. 원본 응답이나 백업을 다시 확보해야 합니다.

실제 비밀번호나 API 키 대신 아래 가짜 데이터로 먼저 확인하세요. 실제 서비스에 다시 넣을 데이터라면 해당 API가 ID를 숫자로 받는지 문자열로 받는지도 확인합니다.

## 긴 숫자 ID가 바뀌는지 확인하기

다음 예시를 [JSON 정리·검증기](/json-formatter)에 넣고 **정리하기**를 누르면 숫자 끝자리가 달라집니다.

입력:

```json
{"id":9007199254740993}
```

결과:

```json
{
  "id": 9007199254740992
}
```

현재 도구가 사용하는 숫자 표현에서는 안전하게 다룰 수 있는 정수 범위가 `-9007199254740991`부터 `9007199254740991`까지입니다. 범위를 벗어난 모든 정수가 반드시 달라지는 것은 아니지만, 정수 하나하나의 정확한 구분을 보장할 수 없습니다.

ID를 받는 시스템이 **문자열을 허용하는 경우에만**, 정리하기 전 원문에서 ID를 문자열로 준비하세요.

```json
{"id":"9007199254740993"}
```

이 예시는 정리 후에도 문자열의 숫자가 유지됩니다. 이미 바뀐 `9007199254740992`에 따옴표를 붙여도 원래 ID가 복구되지는 않습니다. 숫자형이 필수인 API라면 자료형을 임의로 바꾸지 말고 큰 정수를 정확히 처리하는 도구를 사용하거나 원문을 그대로 보관하세요.

## 같은 키가 두 번 있으면 마지막 값만 남습니다

다음 예시는 문법 오류로 거절되지 않지만, 정리 후 첫 번째 `state`는 남지 않습니다.

```json
{"state":"draft","state":"published"}
```

현재 도구의 결과는 `{"state":"published"}`에 들여쓰기를 적용한 형태입니다. 이는 **같은 객체 안에서 같은 키가 반복되는 경우**입니다. 서로 다른 객체에 같은 이름의 키가 있는 것과는 다릅니다.

둘 다 필요한 정보라면 원본을 만든 쪽에서 구조를 확인해야 합니다. 배열이나 서로 다른 키로 표현할 수 있는지는 사용하는 서비스의 데이터 규격에 따라 결정하세요. 이 도구는 중복 키 경고나 사라진 값 복구 기능을 제공하지 않습니다.

## 실제 데이터를 처리하는 순서

1. 원문을 별도로 저장하고 사본을 준비합니다.
2. 긴 숫자 ID와 같은 객체 안의 중복 키가 있는지 원문에서 확인합니다.
3. 해당 문제가 있다면 데이터 제공처의 규격에 맞게 원본을 수정하거나 다른 도구를 선택합니다.
4. 사본을 정리하고 중요한 ID와 항목을 원문과 비교합니다. **한 줄로 줄이기**도 같은 파싱 과정을 거치므로 우회 방법이 아닙니다.
5. 값과 자료형, 필수 항목을 확인한 뒤 필요한 곳에 사용합니다. 문법 검사만으로 API 요청의 유효성이 검증되지는 않습니다.

## 관련 안내와 도구

아예 오류가 나서 정리가 안 된다면 [따옴표·쉼표·주석과 Windows 경로를 고치는 예시](/community/json-format-errors/)부터 확인하세요. 경로의 역슬래시가 탭이나 줄바꿈으로 해석되는 경우처럼, 숫자가 아닌 문자열도 의도와 다르게 읽힐 수 있습니다. 문법 오류를 고친 뒤에도 이 글의 원본 비교 과정은 필요합니다.

조건을 확인했다면 [JSON 정리·검증기에서 사본으로 결과 비교하기](/json-formatter)를 진행하세요. 원문 그대로의 보존이 필요하거나 큰 정수·중복 키를 다뤄야 한다면 현재 도구의 결과를 원본 대신 사용하지 마세요.
