# 로컬 로그인·지갑 테스트

기존 이메일 링크 인증 및 크레딧 화면을 실행합니다. 새로운 결제 시뮬레이터가 아닙니다.
NICE 결제창·승인·취소 실연동은 이 실행기에 포함되지 않습니다.

## 실행

Node.js 24와 저장소의 프런트엔드 및 node-api 의존성이 필요합니다.
저장소 루트에서 실행합니다.

```powershell
npm run dev:wallet --prefix node-api
```

- 화면: http://127.0.0.1:4321/credits/
- 로컬 메일함: http://127.0.0.1:8788/
- 두 포트를 다른 앱이 사용 중이면 먼저 확인하세요. 화면은 반드시 위 4321 주소로 엽니다.
- 종료: 실행 터미널에서 Ctrl+C.

## 직접 확인할 내용

1. 이메일 형식의 테스트 주소를 입력하고 로그인 링크 받기를 누릅니다.
2. 로컬 메일함을 열거나 새로고침하고 해당 주소의 인증 링크를 누릅니다.
3. 로그인한 주소, 잔액 0개, 비어 있는 내역, 충전 비활성 상태를 확인합니다.
4. 새로고침해도 로그인 상태가 유지되는지 확인합니다.
5. 로그아웃하면 로그인 화면으로 돌아옵니다. 이미 사용한 인증 링크는 재사용할 수 없습니다.

외부 이메일 발송 대신 로컬 메일함으로만 전달합니다. 운영 이메일 키, NICE 키,
Polar 키, 운영 DB를 사용하지 않습니다. API는 127.0.0.1에만 바인딩하고 Host와
Origin을 제한합니다. 인증 링크를 포함하는 메일함은 이 PC의 테스트 용도입니다.
계정·인증 토큰·내역은 메모리에만 존재하며 종료하면 폐기됩니다.
다른 도구의 유료 실행 검증용 서버가 아니므로 이 테스트는 credits 화면에서 진행합니다.

## 확인 결과

2026-11-12 Edge에서 이메일 요청 → 로컬 메일함 → 일회용 인증 → 지갑 잔액
표시 → 로그아웃 → 이미 사용한 링크 거부를 확인했습니다. 실제 외부 메일 전달,
NICE 결제, 운영 DB 영속성 및 운영 배포를 검증한 결과는 아닙니다.
