# Direct purchase result recovery — 2026-11-13

The existing customer staging router now waits for asynchronous wallet authentication and rejects missing/non-string identities. Completed direct-purchase results can be retrieved through authenticated, exact-Origin POST `/customer/result`; `/customer/history` lists up to 20 completed purchases for the current owner and configured merchant. The customer page provides a previous-results selector and restore button. Restoration reads the persisted result without requesting another approval, claiming another entitlement or executing a paid provider. Unknown/other-owner/other-merchant orders remain unavailable.

Validation: 53 existing customer, approval, callback, refund and recovery tests passed, including asynchronous authentication, an unavailable result before completion, restored results without extra runner calls, and cross-account denial. These tests use injected payment/provider responses, not actual NICE approvals or AI output. A broader server assembly check still fails on Windows because the existing private-photo permission check requires owner-only POSIX permissions; that security check was not weakened.

This change remains on the NICE development branch. It does not remove the public AI maintenance gate or wire the original product execution buttons into checkout. Production API rollout, verified existing-wallet backup/durable storage, Google-to-production-wallet authentication, merchant test eligibility, commercial pricing and real provider/browser validation remain incomplete. The existing public Google/credit simulation and PPT are not replaced by this code change. No real payment, production database mutation, API deployment, or external submission occurred.
