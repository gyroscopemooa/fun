# 커뮤니티 글 작성·수동 발행

## 요청 명령

“지금 커뮤 글 작성해줘” 또는 “사진 용량 주제로 커뮤 글 작성해줘”. AGENTS.md에서 이 지침을 불러온다.

## 작성 원칙

목표는 글 개수가 아니라 실제 문제 하나의 해결과 관련 안내·도구 사용으로의 자연스러운 연결이다.

1. 제공된 검색 실적 CSV가 있으면 노출은 많지만 클릭이 적은 검색어를 검토한다. 없으면 실제 문의나 확인 가능한 도구의 제약에서 질문을 고른다. 검색량·순위·인기도·사용 후기·사용자 문의를 만들어내지 않는다.
2. src/content/community 및 src/lib/guides의 기존 글을 확인한다. 같은 질문에 답한다면 기존 글을 보완한다. 새 글은 구분되는 질문 하나만 담당한다.
3. 실제 src/pages 및 연결 컴포넌트에서 기능을 확인한다. 제목 → 첫 문단의 답 → 준비 조건과 실행 순서 → 제약과 대안 → 관련 안내 → 도구 실행 링크 순서로 작성한다. 직접 사용하지 않은 기능은 후기처럼 쓰지 않는다.
4. 관련 기존 글과 서로 연결하고 링크 문구에 목적을 쓴다. 관련 없는 글은 연결하지 않는다. 기존 파일명과 주소는 유지한다. tags가 겹치는 공개 글은 상세 하단에 최신순으로 자동 노출되며 tools가 일치하는 가이드도 자동 연결된다. 이 연결은 재빌드 시 과거 글에도 적용된다.
5. 과거 본문을 일괄 재작성하지 않는다. 필요한 수정만 하고 updated를 실제 수정 날짜로 기록한다.
6. 외부 커뮤니티에 쓸 글은 링크 없이도 핵심 답을 담고 운영자 관계를 밝힌다. 규칙에 맞춰 링크를 넣으며 같은 홍보글을 복제하지 않는다. 외부 링크가 검색 순위 상승을 보장한다고 설명하지 않는다.
7. 실제로 수집된 질문 해결 반응·링크 클릭·도구 사용 데이터를 통해 개선한다. 현재 게시판 전용 성과 집계 및 검색 실적 자동 연동은 구현하지 않았다. 데이터가 없으면 성과를 주장하지 않는다.

## 파일 형식

src/content/community/<영문-고정-주소>.md에 저장한다. 아래 예시를 복사한다. draft: true는 목록, 상세 경로, 사이트맵에서 제외된다. 검토 후 false로 바꾼다. published와 updated는 YYYY-MM-DD, tools는 존재하는 사이트 내부 주소를 사용한다.

```yaml
---
title: "누가 어떤 상황에서 겪는 문제인지 드러내는 제목"
description: "문제와 해결 내용을 설명하는 검색·목록 요약"
question: "이 글이 해결하는 질문 한 가지는 무엇인가요?"
category: "사진·이미지"
published: "2026-10-29"
tags: ["이미지"]
tools:
  - href: /image-resizer
    label: 사진 크기 조절하기
draft: true
---
첫 문단에 핵심 답을 씁니다.
```

## 수동 업로드·발행

1. 작성한 .md 파일을 src/content/community 폴더에 추가한다. 파일명이 게시글 주소이므로 게시 후 변경하지 않는다.
2. 내용·기능·내부 링크를 검토하고 draft: false로 전환한다.
3. npm run build로 검증하고 npm run preview에서 /community/ 및 글 상세를 확인한다.
4. 기존 사이트 배포 절차로 빌드 결과를 배포한다. 로컬 파일 작성만으로 운영 사이트에 게시되지는 않는다.

## 작업 결과에 반드시 포함

- 제목과 본문을 담은 파일 및 미리보기 주소
- 해결하는 질문 한 가지
- 연결할 기존 글과 링크 위치, 실제 수정 사항
- 추가 확인이 필요한 기능·사실 및 로컬 검증 결과
- 로컬 작성인지 운영 사이트 발행까지 완료했는지
